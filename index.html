Evaluación de la capacidad de los procesos

La familia ISO/IEC 33000 proporciona un marco para evaluar procesos de sistemas, software y servicios de TI. Permite identificar fortalezas, debilidades y oportunidades de mejora.

Su enfoque está en la forma en que se ejecuta, gestiona, controla y mejora el trabajo de una organización.

Conocer ISO 33000

Requisitos y evaluación de la calidad del software

ISO/IEC 25000, conocida como SQuaRE, reúne normas para especificar requisitos, medir y evaluar la calidad de productos de software y sistemas.

Considera características como funcionalidad, rendimiento, compatibilidad, seguridad, fiabilidad y mantenibilidad.

Conocer ISO 25000

Dos perspectivas que se complementan

ISO/IEC 33000 examina la capacidad de los procesos utilizados para desarrollar y mantener soluciones. ISO/IEC 25000 examina la calidad del producto obtenido.

Su aplicación conjunta permite mejorar la manera de trabajar y el software que se entrega.

Evaluar procesos para mejorar resultados

La capacidad de un proceso expresa el grado en que puede alcanzar sus resultados de manera consistente. La evaluación permite conocer qué funciona, qué presenta dificultades y dónde se requiere mejorar.

FAMILIA ISO/IEC 25000 · SQuaRE

La calidad se diseña, se mide y se evalúa

ISO/IEC 25000 reúne modelos y orientaciones para definir requisitos de calidad, seleccionar medidas y evaluar productos de software. No basta con que una aplicación funcione: también debe responder a las necesidades de sus usuarios.

La familia aborda la calidad del producto, la calidad en uso y la calidad de los datos.

ISO/IEC 25000: MODELOS DE CALIDAD

La familia SQuaRE organiza diferentes perspectivas para evaluar la calidad.

Calidad del producto

25010

Características del producto

  • Adecuación funcional
  • Eficiencia del desempeño
  • Compatibilidad
  • Capacidad de interacción
  • Fiabilidad
  • Seguridad
  • Mantenibilidad y flexibilidad

Calidad en uso

25019

Resultados para el usuario

EXPERIENCIA DE USO
  • Efectividad
  • Eficiencia
  • Satisfacción
  • Ausencia de riesgo
  • Cobertura del contexto

Calidad de datos

25012

Características de los datos

  • Exactitud
  • Completitud
  • Consistencia
  • Credibilidad
  • Actualidad
  • Accesibilidad
  • Trazabilidad

DIVISIONES DE LA FAMILIA ISO/IEC 25000

Las divisiones agrupan normas y documentos según su propósito.

ISO/IEC 2500n

Gestión de calidad

Conceptos generales, modelos de referencia y guía para gestionar la evaluación.

ISO/IEC 2501n

Modelo de calidad

Modelos para la calidad del producto, calidad en uso y calidad de datos.

ISO/IEC 2502n

Medición de calidad

Orientaciones y medidas para cuantificar características de calidad.

ISO/IEC 2503n

Requisitos de calidad

Definición y especificación de requisitos de calidad para el producto.

ISO/IEC 2504n

Evaluación de calidad

Procesos y recomendaciones para evaluar productos de software.

ISO/IEC 25050–25099

Extensiones

Normas y documentos complementarios para escenarios específicos.

¿CÓMO SE COMPLEMENTAN?

Ambas familias aportan perspectivas diferentes para fortalecer el desarrollo de software.

ISO/IEC 33000

Enfoque en el proceso

Analiza cómo la organización ejecuta, gestiona y mejora sus procesos.

Pregunta clave:

¿Estamos trabajando con procesos capaces y controlados?

+
ISO/IEC 25000

Enfoque en el producto

Analiza las características y los resultados de calidad del software y sus datos.

Pregunta clave:

¿El producto cumple los requisitos y las necesidades de calidad?

Resultado: procesos mejor gestionados y productos de software evaluados con criterios de calidad.

APLICACIÓN EN UN PROYECTO REAL

Ejemplo: desarrollo de una plataforma web para una institución educativa.

Se revisa cómo se reciben los requisitos, se planifican las tareas, se desarrolla, se prueba y se controlan los cambios.

ISO/IEC 33000 Evaluación del proceso de desarrollo

Se comprueba que las matrículas, consultas de notas y certificados funcionen correctamente y sean fáciles de utilizar.

ISO/IEC 25000 Evaluación de la calidad del producto

Los resultados permiten priorizar mejoras en el proceso y corregir características del sistema que no cumplen lo esperado.
